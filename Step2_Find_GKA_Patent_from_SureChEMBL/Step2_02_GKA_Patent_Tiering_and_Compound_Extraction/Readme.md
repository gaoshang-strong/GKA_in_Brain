把 Step2_01 的 GCK 相关专利**分层**，从选定层抽取**权利要求里的化合物**，
并给每个化合物算噪声指标 —— 得到 SureChEMBL 侧独立的 GKA 候选池。

输入：`Step2_01_GCK_Related_Patents.csv`（35,793 篇 / 7,620 同族）

**纯规则**，不调 API、不用 LLM、不用 ChEMBL 种子。

## 一、专利分层

Step2_01 是召回优先的大网，7,620 个同族里多数只是顺带提了一句 glucokinase。
这里按**规则能拿到的证据**分三层，只有 L1 / L2 进后续。

| 层 | 定义 | 专利 | 同族 |
|---|---|---:|---:|
| **L1** | 标题写 `glucokinase activator`（`title_says_activator`） | 638 | **143** |
| **L2** | （标题提 GCK **或** 权要提 GCK **或** 说明书提 GCK ≥3 次）**且**权要里有化合物 | 4,283 | **1,388** |
| L3 | 其余 | 30,872 | 6,820 |

### ⚠ L2 的第三支是补出来的：典型化合物专利在权要里根本不提靶点

初版 L2 只认「标题提 GCK 或 权要提 GCK」，实测漏掉 80 个 Step1 已知分子。
装着它们的 L3 专利长这样：

| 标题 | 权要提 GCK | 说明书提 GCK | 权要化合物 |
|---|---:|---:|---:|
| `Therapeutic agents` | **0** | 1–252 | 256 |
| `2-(3,5-DISUBSTITUTEDPHENYL)PYRIMIDIN-4(3H)-ONE DERIVATIVES` | **0** | 37 | 119 |
| `NOVEL 2-PYRIDINECARBOXAMIDE DERIVATIVES…` | **0** | 32 | 88 |
| `Heteroaryl benzamide derivatives for use as GLK activators` | 0 | 7 | 100 |

**标题是纯化学名、权利要求里一次都不提靶点**——这正是化合物专利的标准写法，
靶点只写在说明书。加上「说明书提 ≥3 次」这一支后补回 79/80。

阈值 3 是量出来的：说明书提 1–2 次的有 23,787 篇（顺带列举靶点），
≥3 次的只有 2,364 篇，**信噪比在这里陡变**。

> 顺带发现一个仍未修的漏点：**`GLK` 也是 glucokinase 的常用缩写**
> （AstraZeneca 系列用它），Step2_01 的标题正则没覆盖，
> 标题含 `GLK activator` 的有 47 篇 / 10 同族。
> 但 `GLK` 单独用会撞到 **MAP4K3（`HGNC:6865`）** 和植物基因 Golden2-like，
> 要加必须带上下文（`GLK\s+activator`），是 `GCK`→MAP4K2 那个坑的翻版。
> 本轮靠 L2 第三支已捞回大部分（那批 `hit_desc` 中位 7）。

L1 是唯一带**方向信号**的层——标题直接说了是激活剂。
L2 要求「权要里有化合物」，是为了排掉纯方法/用途权利要求（没有化学主体，抽不出东西）。

**L3 记录但不进后续**：7,102 个同族里绝大多数是在说明书里罗列靶点时提了一句
（实测 42% 的权要命中专利只提 GCK 一次），信噪比太低。
需要时可以回 Step2_01 主表重新取。

## 二、抽化合物

```
L1 + L2 的专利  →  patent_compound_map (field_id = 2)  →  compounds
```

**只取 `field_id = 2`（权利要求）**。说明书里的化合物大量是背景技术引用的他人化合物，
在锚定步骤保留是为了召回，到了抽分子这步必须收紧。

实测 L1+L2 权要化合物 **25,256 个**。

## 三、⚠ 专利的层级不能继承给化合物

这是本步骤最关键的一条，与 CLAUDE.md 里 Step1_04 那条陷阱同构：

> assay 有目的性，但 assay 里的分子未必都符合那个目的

换到专利：**一篇 GKA 专利的权利要求里，不是每个化合物都是 GKA。**

实测 `EP-4725482-A1`（GLUCOKINASE ACTIVATOR FOR COGNITIVE DISORDERS）
权要里只有 3 个化合物：

| MW | SMILES | 是什么 |
|---:|---|---|
| 180.156 | `O=C[C@H](O)[C@@H](O)[C@H](O)[C@H](O)CO` | **葡萄糖**（开链式） |
| 180.156 | `OC[C@H]1OC(O)[C@H](O)[C@@H](O)[C@@H]1O` | **葡萄糖**（环式） |
| 462.927 | `CC(C)C[C@@H](C(=O)Nc1ccn(C[C@@H](O)CO)n1)N1CC(Oc2ccccc2Cl)…` | 多格列艾汀 |

**3 个里 2 个是葡萄糖**——权要写「激活葡萄糖激酶」必然提到底物，抽取管道就把它注册成化合物了。

所以化合物层需要**独立的判别**，见下。

## 四、噪声指标（全部算成列，不直接删行）

| 指标 | 算法 | 砍掉什么 |
|---|---|---|
| **`n_global`** | 该化合物在**全库**出现的专利数 | 水、溶剂、试剂、元素符号 |
| `n_in_L1` / `n_in_L2` | 在选定层里出现的专利数 | — |
| **`specificity`** | `n_in_sel / n_global` | **葡萄糖这类底物**：在 GKA 专利里常见，但全库更常见 |
| `mol_weight` | 来自 `compounds` | 元素、气体、聚合物 |
| `is_single_atom` / `has_carbon` / `rdkit_valid` | RDKit 现算 | `[C]`、`[Si]`、`[Cu]` 这类抽取残渣 |

`n_global` 的区分力实测（L1 权要化合物）：

| | `n_global` | 例 |
|---|---:|---|
| 最脏 | 10,983,177 | `O` 水 |
| | 9,086,379 | `C` 甲烷 |
| | 8,721,971 | `[C]` 碳原子 |
| 多格列艾汀 | 187 | |
| 最干净 | 10 | 某砜类 GKA |

**特异性差 4 个数量级**（多格列艾汀 0.18 vs 水 0.00002）。

### 阈值（每一条都用阳性对照标定过，误杀 0 个才留下）

```
n_global   <= 10,000      对照最大值 316，留 30 倍余量
mol_weight 在 250 – 700    对照范围 378.5 – 559.8
rdkit 可解析 且 含碳 且 非单原子
```

**`specificity` 与 `n_in_sel` 只作标注列，不参与 keep 判定。**

### ⚠ 初版的教训：拍了阈值没验对照，12 个已知 GKA 只有 3 个通过

| 被否掉的规则 | 误杀 | 为什么错 |
|---|---:|---|
| `specificity >= 0.01` | 2 | **越重要的药被后续专利引用越多**，全库出现数越大、特异性反而越低（AZD-1656 0.0063、Piraglitin 0.0072）。这个指标对成名已久的药有系统性偏见 |
| `n_in_sel >= 2` | 5 | 理由本身就错：一个药通常**只在它自己那一族专利的权要里**被具体画出来，别处提它是当现有技术、出现在说明书。**「只出现在 1 篇权要里」恰恰是原研化合物的特征** |

这与 CLAUDE.md 里「**阈值要用阳性对照标定，不能按整体分布拍**」是同一条。
**脚本现在自带 `selfcheck_controls()`，误杀会直接报警**——任何阈值改动都要先过这一关。

实测：keep **17,941 / 25,256**（71.0%），阳性对照 **9/9 全部通过**。
葡萄糖照样被挡住（`n_global` 244 万，且 MW 180 不在窗口内）——
**两条安全规则已经够用，特异性那条是多余的**。

## 五、⚠ 这套规则解决不了的

1. **特异性高 ≠ 是 GKA。** 合成中间体、砌块只出现在同一批专利里，特异性同样高。
   实测样例：`NC(=O)c1ncc(Cl)s1`(MW 162.6)、`Fc1cn[c]s1`(MW 102.1) 特异性很高，
   但明显是中间体。分子量下限 250 能挡掉大部分，**挡不干净**。
2. **判不了「是不是权利要求主张的主体」。** 通式枚举物、中间体、参比化合物
   在 `patent_compound_map` 里没有任何区别——要分开只能读权利要求原文。
3. **判不了方向。** 只有 L1 的标题信号，而且那是**专利级**的，不是化合物级的。
4. **马库什通式的枚举程度不均。** 有的专利枚举出上万个结构，有的只画通式，
   `n_compounds_clms` 差几个数量级，会让「按化合物计数」的统计被大专利带偏。

## 六、独立性

**不用 ChEMBL 做任何筛选。** Step1 的 787 个分子只在报告里做**事后比较**——
「SureChEMBL 独立找到的池子，与 ChEMBL 侧重叠多少、新增多少」，
这是 Step2 的核心问题，用 ChEMBL 筛就成循环论证了。
